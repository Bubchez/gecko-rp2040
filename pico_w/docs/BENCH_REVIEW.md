# T09 isolated bench preparation review

Reviewed feature-branch T09 commit `45437cf7fbcd3c821a275a036a1423777985b826`.
Scope: tools/firmware needed to prepare isolated Pico simulation validation;
offline tests and compilation only in this workspace. No physical device access,
automatic flashing, Gecko connection, I2C, actuator execution, external application
changes or T10. Instruction scope is committed separately.

| Finding and evidence classification | Resolution and acceptance |
|---|---|
| **Reproduced host software defect:** T09 provision_usb.py treated each read_until timeout result as a complete line. Injected CONFIG_ then SAVED causes its actual MIT main to exit without confirmation despite a complete acknowledgement. No real serial port involved. | Shared bounded SerialLink preserves fragments across empty reads, uses an absolute deadline/line/total limits and rejects short writes. Legacy helper and new runner share the fix. Transcript: BENCH_REPRODUCED.txt; byte/time-double regressions. |
| **Host-verified cross-platform defect:** raw source-byte digests change with Windows CRLF checkout, even when firmware text is unchanged. | Canonical LF hashing for native identity and broad source manifest digest. Temp-file tests change LF to CRLF and retain both digests. Actual native Windows cross-build is not claimed. |
| **SDK-inspected integration constraint:** stdio CDC expects DTR; default full-speed TX FIFO is 64 bytes and T09 selected zero output timeout. A long INFO response can exhaust it and truncate. No device timing measurement exists. | Selected Pico CDC uses DTR true at 115200; baud/vendor reset mechanisms remain disabled. Bounded native INFO formatter (max 512) and fixed TX FIFO 1024, still nonblocking. Maximum identifier/counter/IP and malformed-field formatter tests pass. Real Windows buffering remains unverified. |
| T09 firmware_version alone cannot correlate an installed binary to the reviewed UF2. | Native input build ID generated by CMake, embedded in UF2 and returned by USB INFO/API capabilities; exact manifest/source/USB/HTTP match required. Build checks compiled binary contains its ID. This is reported correlation evidence, not authenticated attestation/readback. |
| Manual AP changes would add operator work and confuse an induced reconnect with genuine AP failure. | Local USB WIFI_RECONNECT only when online: close listener, leave Wi-Fi, bounded policy backoff/rejoin, saturated diagnostic counter. Tests cover policy and full runner with radio doubles. Hardware run must observe offline state plus renewed counters/same boot/fresh continued simulation. AP-failure scenarios remain explicitly unverified. |
| Test report dumps/exception scrubbing can leak credentials, host paths or raw state. | Allowlist-only versioned report schema. No raw serial/HTTP, exception strings, addresses or device IDs. Canary-bearing malformed replies/errors are absent from reports; bootstrap failures carry a fixed stage enum. Full pass requires every ordered check to pass. |
| First-run Windows setup must handle missing dependencies, ACLs, native quoting/stderr and paths with spaces. | Single PS5.1-compatible entry point, pinned local venv dependencies, direct argument arrays, quiet bootstrap status checks, current-user/SYSTEM private ACLs, bounded/reused tokens and no flashing code. PowerShell 7.4.6 Linux parser/VerifyOnly/bootstrap-failure/path-space tests run; Windows ACL/PS5.1 execution remains unverified. |

The bench workflow runs against the existing read-only v1 and simulation/session
core. Only optional capabilities.firmware_build_id is added; no HTTP provisioning,
reconnect, raw I2C, scenario or actuator execution route exists. Synthetic policy,
unavailable fields, temperature units, oldest-fragment freshness, source confidence
and legacy licence restrictions are unchanged. The original Arduino/ESPHome tree
and separate Agile Alert/Pi Zero applications are preserved.

Offline flow tests double only the USB identity/radio boundary and run actual native
protocol/session/HTTP parser/serializer. A separate test runs the bounded socket
client against real loopback HTTP. These are **not hardware bench results**. The
committed example report is VerifyOnly with device steps not_run, not a manufactured
device pass. See ISOLATED_BENCH.md for the operator command and report interpretation.
